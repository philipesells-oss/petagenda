# Story 1.6 — Gerenciamento de Clientes e Pets

**Epic:** 1 — MVP Foundation
**Status:** Done
**Agent:** @dev (Dex)
**Estimated:** 5-6h
**Depends on:** Story 1.2, Story 1.3

---

## Descrição

Implementar CRUD completo de clientes (tutores) e pets, com perfil rico contendo histórico de atendimentos, fidelidade e tags. Base para todo o fluxo de agendamentos e mensagens.

---

## Acceptance Criteria

- [x] Lista de clientes em `/clients` com tabela (nome, telefone, tags, último atendimento, total gasto, status)
- [x] Busca por nome/telefone com debounce
- [x] Filtros por status (active/inactive/blocked) e tag (vip/novo/atrasado/inativo)
- [x] Paginação 20 por página
- [x] Formulário `/clients/new` com validação (telefone BR, WhatsApp opt-in)
- [x] Perfil do cliente `/clients/[id]` com abas: Pets, Histórico, Mensagens
- [x] CRUD de pets dentro do perfil (card + dialog com form)
- [x] Upload de foto do pet para Supabase Storage bucket `pets`
- [x] Server Actions com zod validation e `revalidatePath`
- [x] Componente `DataTable` reutilizável (filtros, busca, paginação)

## Notas Técnicas

- RLS isola por `tenant_id` automaticamente via policies (ver Story 1.2)
- Tenant atual é obtido via `getCurrentUser()` em server actions
- Upload de foto usa bucket público `pets/{tenant_id}/{pet_id}.{ext}`
- Tags são `text[]` — sugestões iniciais: `vip`, `novo`, `atrasado`, `inativo`
- Telefone formatado (xx) xxxxx-xxxx; persistido apenas dígitos
